动态物体滤除：选型历程与最终实现

g1d_ws · 宇树 G1-D · 头部倒装 Livox Mid-360S · FAST-LIO2 · Nav2 代价地图 · 2026-11 · 对应文档 docs/DYNAMIC_OBJECTS_STUDY.md

1. 结论速览

动态物体滤除最终由四道互补的机制完成，外加一道可选的相机增强。它们共同保证两件事：点云地图不留行人"拖影"，导航代价地图不被已经离开的人干扰。

#机制解决什么运行位置
1M-detector 逐点运动标注每帧里哪些点属于运动物体g1d_lio（CPU）
2FAST-LIO 地图插入把关：动态邻域排除、延迟 3 帧、按盒回溯删除行人不进 ikd-Tree 地图g1d_lio
3代价地图：视线穿透清除 + 盲区保护 + 0.8 s 动态层人走过后 1 s 内恢复空闲，看不见的障碍不被误清g1d_nav
4导出地图 DUFOMap 清理清掉漏网的残留（尤其检测器启动前的几秒）g1d_web（子进程）
5相机人员分割（可选）站着不动的人（几何方法看不出）g1d_perception（GPU）
≤ 0.85 s行人走过后代价地图拖影消失（要求 ≤ 1 s）
0.74 / 0.90M-detector 召回：完整 LIO 闭环 / 真值位姿；静态误检 ≈ 0
−67 ~ −83 %FAST-LIO 地图中行人走廊的残留点
95 %DUFOMap 导出清理移除拖影，墙体保留 ≥ 99.5 %

以上为仿真结果（C++ 闭环仿真 + 合成数据）。真机验收（Orin NX 耗时、真人场景、相机标定与模型训练）尚未进行，见第 15 节。

核心原则任何来源判为动态的点，都不进地图、不进静态代价层，只进一个会自动过期的动态层；guard 反射层仍使用当前帧全部障碍点。漏检只会让残影多留一会儿，误检只会少记一个静态点，都不会让机器人撞上东西。

2. 问题从哪里来

改造前，系统对动态物体没有任何专门处理。各环节的情况如下：

位置改造前的做法动态物体的影响
FAST-LIO2 ikd-Tree每帧配准后，降采样点全部加入地图行人轨迹一直留在地图里（直到移出约 60 m 范围）；人多时可能拉偏后续配准
g1d_nav 体素层当前帧先沿射线清除、再标记；没有时间衰减只有射线恰好穿过才清除；没有回波的方向、盲区、视场外的拖影会残留
Web 累积地图 / 导出体素只增不删拖影全部进入导出的 map.pcd 和 grid.png
guard 反射层只用当前帧不受影响
两个问题要分开解决地图要求"动态点永不入库"，宁可多删，因为静态结构之后会被补回来；代价地图要求"刚看到的要避开、离开的要尽快忘掉，但盲区里的不能忘"。

3. 选型历程

3.1 四轮决策时间线

第一轮 · 按 Orin NX 算力调研

几何方法为主，相机分割为可选增强

调研了 M-detector、DUFOMap、Dynablox、ERASOR、STVL 等几何方法，FAST-LIO 现成改版，以及 4DMOS / MapMOS 等学习方法。结论：在线检测用 M-detector，地图清理用 DUFOMap；激光雷达学习模型不划算。
第二轮 · 开发环境换成 RTX 5090 主机 + Jetson Thor

算力不再是瓶颈，但结论变成"几何做底座，学习补短板"

学习模型补两个几何方法的固有短板：静止的人（语义分割）和速度预测（场景流）。5090 让"几何方法当老师、学习模型当学生"成为可能。
第三轮 · 评估"5090 推理 + Wi-Fi 下发给 PC2"与 SAM3D

SAM 3D 不适合；SAM 3 只做辅助语义和教师标注

"SAM3D"三种指代都不做运动判断；Wi-Fi 结果会晚到、偶尔不到，不能进避障回路。更好的用法是 SAM 3 在 5090 上标注，蒸馏小模型在 PC2 本地跑。
第四轮 · 最终方案（决策记录）

安全实时的一切都在本地几何完成；5090 负责离线与训练

分 P1–P4 四期：P1 代价地图、P2 M-detector + 地图清理、P3 相机识别静止的人、P4 场景流预测（换 Thor 后）。本次实现了 P1–P3，P4 只做了训练数据导出。

3.5 5090 / Thor 下的重新选型

换成 RTX 5090 主机（Blackwell sm_120）和 Jetson Thor（sm_110，JetPack 7）后，算力不再是瓶颈，但结论不是"用学习模型替换几何方法"，原因有三：

  1. 几何方法不需要训练数据，直接适用于 Mid-360S + 倒装 + 室内；现成的激光雷达学习模型都在车载多线雷达上训练，在稀疏 / 非车载雷达上泛化很差 [7]。
  2. 几何方法有两个固有短板正好由学习模型补：静止的人（语义模型按类别识别）和速度预测（场景流给每点速度，可做 1–2 s 占据预测）。
  3. 5090 让"几何当老师、学习当学生"可行：SeFlow 就是用 DUFOMap 的动态标签作伪标签，自监督训练场景流网络 [35]。

由此形成的分层组合：

工具链风险稀疏卷积库对 Blackwell 支持不完善：官方 MinkowskiEngine 不支持 sm_120 [26]，spconv 需源码编译 [30]；Isaac ROS 4.0 的 nvblox 动态 / 人体分割模式不支持激光雷达输入 [34]。这也是 4DMOS / MapMOS 继续不被推荐的原因。

无线远端推理的约束：Wi-Fi 延迟有长尾，网络过载时可达 500 ms 且会丢消息 [49]，远端结果一定会晚到、偶尔不到。由此得出三条原则：

  1. 远端结果不能进避障安全回路；guard、M-detector、体素层全部本地运行，断网照常工作。
  2. 远端语义只用于对时延不敏感的环节：判定哪些点不入库（已入库的用 ikd-Tree 区域删除回溯清除）、生成训练伪标签。
  3. 更推荐"大模型在 5090 当老师，小模型在 PC2 本地跑"：SAM 3 给自录数据标注，蒸馏 YOLO-seg 部署到 PC2 自己的 GPU，彻底去掉无线依赖。

3.7 最终决策

原则安全和实时相关的一切都在机器人 PC2 本地运行，且只依赖几何方法；5090 主机负责离线处理、大模型标注和训练；学习模型只补几何方法的短板（静止的人、速度预测），永远不是唯一依据。
运行位置内容
PC2（Orin NX，机载，必需）FAST-LIO2 + M-detector；代价地图：静态体素层（射线清除 + 视线证据清除 + 盲区 / 遮挡保护）+ 动态层 + 底盘雷达层；guard 不变；P3 起加本地 YOLO-seg
5090 主机（离线）DUFOMap 清理导出地图；SAM 3 生成"人"掩码蒸馏小模型；DUFOMap 伪标签训练场景流
Thor（将来替换 PC2）场景流上机，代价地图增加预测层

明确不采用：SAM 3D（不做运动判断）、Pointcept SAM3D（离线、秒级）、4DMOS / MapMOS（部署难、泛化差）、当前版本 nvblox 动态模式（不支持激光雷达）、任何依赖 Wi-Fi 的在线推理进入避障回路。

阶段内容验收指标状态

P4 预测场景流训练与上机、预测层迎面行人提前避让换 Thor 后已有训练数据导出

5. 第一道：M-detector 逐点运动标注

5.1 原理

M-detector 把最近约 1.6 s 的扫描按传感器位姿投影成 4 张球面深度图（每张覆盖 0.4 s），然后对当前帧每个点检查它和历史深度图的遮挡关系：

5.2 移植与接入

  1. 先原样入库：DynObjFilter.h/.cpp、types.h、parallel_q.h、mid360.yaml、LICENSE 原样提交（hku-mars @ 0645dab），之后每处修改都可在 git 历史中追溯。
  2. 只改基础设施，判据原样：去掉 ROS（参数改由 ParamSource 读取，名字保持上游的 dyn_obj/…）、OpenCV、PCL I/O；std::execution::par（依赖 TBB）换成 OpenMP；boost::shared_ptr 换成 std::shared_ptr；删除依赖完整 PCL 的 DBSCAN 聚类阶段。编译为独立的 GPL-2.0 静态库 g1d_mdetector。
  3. 接入位置：FAST-LIO 在 EKF 更新之后、map_incremental() 之前调用标注回调，输入是去畸变后的完整扫描（雷达坐标系）和雷达在 LIO 世界系中的位姿。
  4. 点数上限：每帧超过 max_points（配置 12000）就先抽稀送检，结果再按体素扩散回全部点（M-detector 的点池按每帧点数预分配，必须设上限）。

5.3 体素投票（替代原 DBSCAN 聚类）

M-detector 原始输出有孤立误检，也会漏掉人体边缘。我们在世界坐标系里按 0.15 m 体素做两步修正：

  1. 投票：体素被判为动态需同时满足：体素内动态点占比 ≥ 0.4，且 3×3×3 邻域内动态点 ≥ 3（去掉孤立误检）。
  2. 膨胀：向有点的相邻体素扩展一格，补全贴地的腿部、人体边缘；这一步也把标签扩散给被抽稀掉的点。

6. 第二道：FAST-LIO 地图插入把关

机制为什么需要
动态邻域排除FAST-LIO 入库的是 0.3 m 降采样后的"质心点"，可能混合了人体和背景；只排除标签点本身不够，所以排除整个邻域。
延迟 3 帧M-detector 单帧召回约 0.7，任何一帧漏检都会让那部分人体永久进入地图。人 0.3 s 内只移动约 0.3 m，某帧漏检的部分通常在下一帧被邻近检出 —— 仿真中残留因此再减一半。
按盒回溯删除补救已经入库的点（例如人站着时没被标出、之后被相机确认）。
配准不受影响延迟只作用于"新点入库"，当前帧仍与已有地图匹配；Mid-360 是 360° 视场，转身不会让大片区域突然缺图。仿真中开启后定位误差不变（0.03–0.04 m）。

7. 第三道：代价地图

7.1 静态体素层与"视线穿透清除"

体素层每个栅格存一列高度位掩码（0.08–1.85 m，每 0.1 m 一格）。改造后它只用静态点标记，清除有两种：

  • 射线清除（原有）：雷达到每个回波（含动态点）的三维射线穿过的体素被清除，只清射线真正穿过的高度，桌面这类悬空障碍不会被误清。但 Mid-360 是稀疏非重复扫描，射线不一定恰好穿过拖影所在的体素。
  • 视线穿透清除（新增）：用"方向"代替"射线"，覆盖面更大，同时保证看不见的不清。
  1. 把当前帧所有回波（静态 + 动态）按方向分成 2° 的格子，每格记下最近回波的距离。
  2. 对 6 m 内每个已占据体素，算出它的方向和距离 r：若该方向格有回波，且 r < 最近回波距离 − 0.2 m（余量），说明视线越过了它，记一次证据（每个体素一个 2 位计数器）。
  3. 证据达到 2 帧即清除；期间该体素一旦再次被静态点标记，计数器归零（对细杆等不稳定目标更稳）。
  4. 保护规则：方向格里没有回波（车身遮挡、视场外、雷达视场下方）不积累证据；距雷达 0.6 m 以内的体素不参与；没有任何按时间的衰减。
为什么不用原方案的"视场锥加速衰减"STVL 式衰减基于"视场锥内的体素应该每帧被看到"的假设，但 Mid-360 非重复扫描单帧覆盖不完整，车身还会遮挡视场锥的一部分，时间常数很难定。改用"有证据才清"后，不存在任何因为看不见而误清的路径，比衰减更安全。

7.2 动态层

  • 动态点（M-detector 标签）和相机人员点只标记这一层：栅格记录最后一次被看到的时间，0.8 s 内为致命障碍，之后自动消失。高度带与体素层相同（0.08–1.85 m），只记 6 m 以内。
  • 动态点的射线和方向回波仍参与体素层清除：人站过的地方如果之前被当成静态，也会被清掉。
  • 相机人员点（NavCore::onDynamicPoints）：超过 0.5 s 的旧数据丢弃；先清除这些点周围 0.15 m（上下各一层）的体素 —— 处理 M-detector 漏检、已被当成静态的人 —— 再标记动态层。

7.3 与 guard 的关系

发给 guard 反射层的 obstacle_points 仍包含动态点：guard 不区分动静，只看"前方扫掠路径上有没有东西"。所以无论动态标签对不对，近距离停车行为完全不变。

8. 第四道：导出地图 DUFOMap 清理

前三道都是在线的，仍有两类残留躲不过：检测器刚启动、还没有历史深度图的头约 2 s；以及各帧都漏检的部分。导出地图时用 DUFOMap 离线再清一遍。

  1. 累积地图只收静态点：Web 端按 5 cm 体素累积 registered_cloud 中 dynamic = 0 的点。
  2. 关键帧录制：建图时自动录制（移动 0.3 m、转 0.3 rad 或间隔 5 s 一帧），存到 recordings/<时间>/frames/*.pcd。格式与 KTH DynamicMap 基准 / DUFOMap 工具相同：世界系点云，传感器位姿写在 PCD 的 VIEWPOINT，M-detector 标签写在 intensity 字段（同一体素里动静都有时保留动态标签，作训练正样本）。写入用临时文件 + 原子改名，导出时不会读到半帧。
  3. 导出清理：DUFOMap 依次积累每帧"看穿的空间"（void），然后对累积地图的每个点查询 —— 落在 void 体素里的删除。参数：分辨率 0.1 m、d_s 0.2 m、d_p 1。
  4. 输出：清理后的 map.pcd 和 grid.png，清理前另存 map_raw.pcd，meta.json 记录方法和移除点数。
两个实现细节(1) DUFOMap 在子进程（python -m g1d_web.mapclean）中运行：与 CycloneDDS 同进程时在 Windows 上出现访问冲突；子进程失败时自动退回内置的射线清除。同一个命令也是 5090 上的离线工具。(2) 导出在后台线程进行，大地图清理期间网页不卡。

没装 dufomap 时的射线清除兜底：每帧抽 4000 条射线，沿射线每半个体素采样一次，在回波前 max(2 体素, 距离的 10 %) 处停止（防止掠射的地面射线误清地面）；被"看穿"至少 2 次的体素中的地图点被删除。

9. 第五道（可选）：相机识别静止的人

M-detector 靠"运动"判断，站着不动的人会被当成静态；他之后走开，就会在地图和代价地图里留下"人形障碍"。g1d_perception 用外观识别补上这一块。

  1. 取图：从 teleimager 的 ZMQ 流取头部双目左半幅。图像流不带拍摄时间，按"接收时间 − 延迟"打时间戳（默认 0.06 s，待实测）。
  2. 分割：YOLO-seg 人员实例分割，在 PC2 上以 TensorRT 引擎运行（模型由 5090 上 SAM 3 标注蒸馏而来，见第 10 节）。
  3. 投影：外参链 IMU → 雷达（lio.extrinsic）→ 头部（head_to_livox 的逆）→ 相机（head_to_camera）；相机位姿按图像时间对 LIO 位姿插值（球面线性插值）；把图像时刻前后 0.25 s 内的雷达点投影到图像。腰部 / 升降锁定时头部与雷达刚性相连，直接用雷达位姿最准。
  4. 关联与深度门限：取掩码内的投影点，以 20 % 分位深度作为人体前表面，只保留其后 0.6 m、其前 0.3 m 内的点 —— 掩码边缘和缝隙漏进来的背景墙点因此被拒绝；再用重力对齐的 odom 高度去掉脚下地面点（它们和脚同深度，深度门限分不开）。
  5. 确认：按质心最近邻跟踪，0.7 m 门限；同一人连续 2 帧被看到才算确认，单帧误检永远不会删地图。
  6. 贴地安全的删除盒：盒子在 odom 系中从离地 5 cm 起算、外扩 0.15 m，再把 8 个角点换回 LIO 系取包围盒；人脚下的地面保留。每人每 0.5 s 最多发一次。
  7. 输出：rt/nav/person_points（给 g1d_nav）、rt/nav/map_delete（给 g1d_lio）、rt/nav/perception_status（帧数、人数、删除盒数、分割耗时）。
为什么不进安全回路相机延迟、外参误差、时间戳不准，都只会影响"人消失得多快、清得干不干净"。避障和停车完全由雷达几何（体素层、动态层、guard）负责；这个服务停掉，系统照常工作。

12. 开发中解决的关键问题

① 倒装雷达让 M-detector 召回只有 0.2

完整 LIO 闭环里召回只有 0.07，于是逐个排除假设：

假设实验结论
体素投票删掉了标签对比投票前后的原始标签数原始标签本身就少 → 不是
移植有错误受控单元场景（静止雷达、墙、横穿箱子）召回 0.77、误检 0 → 移植正确
点太稀疏同场景 5000 点每帧0.57，有影响但不是主因
传感器在运动平移 / 旋转0.94 / 0.76 → 不是
静止起步、没有背景历史箱子先静止 2 s 再走0.99 → 不是
雷达倒装同场景把雷达横滚 180°0.29 → 找到了

原因：倒装雷达朝下看，能看到人的腿和脚边的地面，两者深度相同。Case 1 的地图一致性检查在一个窗口（上游为 ±0.3 m × ±0.6 m）内找"与当前点深度相近的历史静态点"，找到就判为"与地图一致"→ 静态。脚边的地面让腿被判为静态；静态的腿留在深度图里，又让躯干落入同样的判断 —— 静态标签沿身体向上传播。把窗口缩到 0.15 m 后召回升到 0.7–0.9，误检仍为 0。

② DUFOMap 论文参数不适合 Mid-360 点密度

合成场景中 d_p = 2 只清出移动物体的 13 %。d_p 是"未知空间"的膨胀格数：Mid-360 每个 0.1 m 体素每帧只被一两条射线穿过，d_p = 2 要求周围两格也都确认为空，大部分移动物体体素因此停留在"未知"。改为 d_p = 1 后清出 95 %，墙体不受影响。另外发现 DUFOMap 对缓慢移动物体的逐帧标签不完整（物体与下一帧位置重叠，被当作命中），但不影响地图级清理。

③ DUFOMap 与 CycloneDDS 同进程时访问冲突

Web 端到端测试在导出地图时挂起；故障转储显示一次 "access violation"。离线复现正常，只有与 DDS 同进程时出现。改为子进程运行（同时作为 5090 离线工具），子进程失败时退回射线清除。

④ 导出改后台线程后测试挂起

原因是 WebSocket 关闭时无限等待一个已经不读数据的对端，而且这个挂起掩盖了测试本身的一处时序竞争（读到的是遥控生效前排队的旧状态）。关闭等待限时 1 s 并在超时时中断连接；测试改为等待"guard 已切换到遥控"的状态。连续 3 次通过。

15. 局限与上机待办

已知局限

  • 人沿雷达视线方向走、或离雷达超过 5 m 时，M-detector 召回偏低（真值位姿下也只有 0.4–0.6）。
  • 站着不动的人只能靠相机识别，需要标定和训练好的模型；相机只覆盖前方视场。
  • 检测器启动后约 2 s 内进入地图的点，只能靠导出时的 DUFOMap 清理。
  • 比里程计漂移还慢的运动无法检出（同类方法共有的限制）。
  • 还没有运动预测（P4，计划换 Thor 后做）。

上机待办（docs/DEPLOYMENT.md P5 节）

  1. Orin NX 上 label_ms < 20 ms；对比开关前后的定位误差（T3 恶化 ≤ 20 %）。
  2. 真人走过：代价地图 ≤ 1 s 恢复空闲；矮箱子进视场下方后保持；导出地图无残留。
  3. 相机标定 → 录数据 → 5090 上 SAM 3 标注、训练 → Orin 上导出 TensorRT → 启用 g1d-perception；验收 3 m 内召回 ≥ 95 %、< 30 ms/帧。
  4. 确认 Orin（aarch64）能否装 dufomap；不能就在 5090 上用 g1d-mapclean。
